台灣公民科技資料庫，這一年做了什麼

大家好，我是 Dong。 今天跟大家分享 civictech.tw，台灣公民科技資料庫：它想解決什麼問題，做了哪些事。 分三段講：網站為什麼長這樣、為什麼要 AI 摘要、資料還能怎麼用。

2012 年，一個預算網站

把幾千億，

  • 每個泡泡是一筆預算

2012 年，有一群工程師做了這個網站：中央政府總預算視覺化。 每個泡泡是一筆預算，越大越多錢，顏色代表比去年多還是少。 金額可以換算成便當、珍奶。 看不懂的項目，還可以按「表示不懂」。 這是 g0v 最早的專案之一。 （g0v 起源的說法請揪松團校稿）

專案沒有停在 2012

從中央，
擴散到地方

  • 預算視覺化產生器：一套工具，做出好幾個縣市的版本
  • 政府預算查詢平台：各縣市預算、互相比較、下載資料
  • 資料不齊，就邀議員一起補
而且這個專案沒有停在 2012 年。 有人把它做成「預算視覺化產生器」，一套工具，就能做出好幾個縣市的版本。 後來也有人做了政府預算查詢平台，可以看各縣市的預算，互相比較，還能下載資料。 這是 116 年的臺北市預算。 你看上面那段藍色的字：臺北市的單位預算書沒有公開，所以平台直接邀請議員、議員助理一起提供資料。 資料不齊，就找人一起補。

整理一下，想參與的人會卡在四個地方。 第一，找不到：我關心某個議題，以前有沒有人做過？ 第二，看不懂：就算知道專案名字，也不知道它在幹嘛。 第三，找不到人：它有什麼資源可以用？要去哪裡討論？ 第四，資料會舊：寫了沒人更新，錯了也沒人改。 今天的三段，就是在回答這四個問題。

給「要去揪新手的那個人」

第一個問題：這網站給誰用？ 我們的答案是：要去揪新手的那個人。 新手不會自己來逛資料庫。 會來的，是想拉朋友入坑的人。 他需要的，是一個連結，丟到群組裡，朋友點開就看得懂。 所以每個專案、每個議題，都有自己的網址。

第二個問題：分類怎麼分？ 以前照聯合國永續目標分，像是「終結貧窮」。 那是在說專案做什麼，不是一般人會想找的方式。 這次我們改用 7 月的需求問卷，127 個人回答他們最想先看哪些議題。 問卷上的 12 個選項，名稱照抄，一個選項就是一類。 問卷沒問到的，再補 5 類，總共 17 類。

每個專案，篇幅都差不多

48%

AI insight：每行限字數，前 10% 只佔 14%

230 個專案由長到短排列，各自用自己的比例尺。每行上限：做什麼 25 字，其他三行各 40 字

其中一個門檻，是 AI 不能偏心：每個專案的篇幅要差不多。 左邊是原本的簡介，230 個專案由長到短排。字數最多的 10% 專案，佔了全部文字的將近一半。 這有什麼問題？把整份資料丟給 AI 問問題，寫得長的專案，在 AI 眼中份量就重，比較容易被推薦。寫得短、或根本沒寫的，就被冷落。 右邊是 AI insight。每一行都有字數上限：做什麼 25 字，其他三行各 40 字。 字數不靠 AI 自律，由程式逐行數，超過就退回重寫。 結果前 10% 只佔 14%，很接近平均。 上限是天花板不是目標：素材少就寫短，不硬湊。

AI 寫，人可以查

每一筆都記下來源

  • 記下參考的網址，優先用網頁封存版
  • 記下哪天、用哪個模型產生
  • 寫不出來就寫「不明」，不硬掰
  • 看到錯了，專案頁上可以建議修改
AI 寫的東西一定會錯，所以每一筆都記下來源，放在資料裡，從 API 就拿得到。 參考了哪些網址，優先用網頁封存版，網站倒了也查得到。 哪天、哪個模型產生的，都寫明。 找不到資料，就寫「不明」，不硬掰。你會在網站上看到很多「不明」，那是刻意的。 看到錯，專案頁上有建議修改。

錯了，誰都能改

  1. 專案頁按「建議修改」
  2. 直接在表單上改，寫一句為什麼
  3. 到 GitHub 送出，或寄信給揪松團
  4. 自動變成一份修改申請
  5. 管理員看過，合併，寫回後台
  6. 隔天同步，網站就更新了
再來是「放得回」。這是這次新做的。 （右邊動畫：在專案頁點「建議修改」，頁面重組成表單。想重播按 R） 每個專案頁都有「建議修改」，點進來就是這個表單，原本的資料已經填好，你直接改。 改完寫一句為什麼要改。 有 GitHub 帳號，就到 GitHub 送出；沒有的話，寄信給揪松團也可以。 送出之後，系統自動把它變成一份修改申請。 管理員看過、合併，就寫回後台。 寫回之前會先比對：如果這段期間有人直接改過後台，就停下來給人決定，不會蓋掉別人改的。 隔天同步，網站就更新了。 資料拿得走，也放得回，這才稱得上「公民科技資料庫」。
